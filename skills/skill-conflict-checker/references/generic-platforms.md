# 通用目录与平台适配

这里的通用目录指直接组织为 `skills/<name>/SKILL.md` 的共享技能来源。它与 `.trae/skills/` 等平台专用位置并列检查，适用于收藏目录、共享库或平台明确导入的技能目录。

[Agent Skills 标准](https://agentskills.io/specification) 规定单个技能目录内的 `SKILL.md`、frontmatter 与可选资源，**不规定所有宿主必须自动扫描顶层 `skills/`**。本 Skill 支持这种共享目录布局；“文件遵循标准格式”和“某平台当前加载这个目录”分别核验。标准于 2026-11-10 核对。

## 共享目录发现

默认检查指定项目下存在的 `skills/`，保留来源类型 `shared-directory`，与目标平台专用来源一起初筛。该行为是本审计工具的发现约定，不是宿主加载规则。只检查指定项目，不自动遍历任意祖先的共享库或用户 home。

其他共享目录可直接指定，路径相对于执行命令的 cwd：

```bash
python3 "<skill-dir>/scripts/checker.py" --platform trae-cn --project "<project-dir>" --skills-dir "<shared-skills-dir>" --output "<local-dir>/inventory.json"
```

`--skills-dir` 可重复，作用于本次所有目标平台；相同共享根不重复添加，平台身份分别保留。加载证据仍分别来自 runtime 或可见配置。只想检查共享库时可用 `--platform generic --no-defaults --skills-dir "<shared-skills-dir>"`；`generic` 是未指定具体宿主的审计标签，不是一种安装目录。

平台专用位置也能通过 manifest 或 `--skills-dir` 明确纳入文件检查，但使用后者只表示用户指定的目录，不证明这是平台默认路径。例如 `.codex/skills/` 在特定版本、历史安装或配置中出现时可以审计；不能仅凭目录名将其当作所有当前 Codex 版本的默认来源。

以下流程补充没有专用适配、原生 API 或缺少本地文件时的处理；它不是“通用目录”的定义。

## 1. 确认宿主能力和目标格式

先从会话和只读查询取得目标名称、版本、运行形态、项目/租户/环境和可见能力。执行审计的宿主与被审计平台可以不同。

| 能力 | 可完成的工作 | 不足时如何处理 |
| --- | --- | --- |
| 本地文件读取、限定搜索 | 枚举源文件、正文和资源引用 | 使用平台的只读列表/详情 API 或用户提供的材料 |
| 终端、Python、YAML 解析器 | 运行本 Skill 的本地确定性脚本 | 保留人工/原生检查，未核验项目标明未知 |
| 平台技能列表、插件配置、只读 API | 核对当前暴露入口、状态和作用域 | 仅报告文件存在，不能推导当前启用或加载 |
| 原生正文、提示模块或规则详情 | 语义对读与治理比较 | 仅有名称/描述时做触发初筛，正文冲突待确认 |
| 官方加载/调用说明、可见裁决规则 | 同名解析、权限及例外判断 | 不套用其他平台规则，保留潜在冲突或待确认 |
| 子智能体 | 分批检查、独立复核 | 顺序执行同一流程，不降低证据要求 |

平台模块可能是 SKILL.md、其他结构化配置、提示文件或托管模块。按宿主实际 schema 解析，明确名称、描述、正文和资源对应哪些字段；不将非 SKILL.md 模块直接判为格式错误，不为了让脚本接受而改写或伪造源文件。

## 2. 从证据确定来源

使用用户指定范围、平台原生列表、可见安装/插件配置和官方说明确定入口。系统、企业、用户、项目、插件、共享来源等仅是可用的描述，不预设平台必须具备这些层次，也不按这些名称自行排列权限。

每个入口保留平台标识、环境、来源 ID、作用域、命名空间、原始名称、实际调用名、路径或原生资源标识，以及四项独立状态：存在、启用声明、列入清单、正文加载。

路径不可见时，用平台提供的资源 ID/详情链接定位。原生接口没有哈希或行号时，不编造：记录版本/修订号（若有）、字段名、标题与精确引用。区分审计读取正文与业务运行时正文加载。

同名覆盖、并存、命名空间、目录继承、导入开关、默认调用和禁用行为均需目标证据。文件自称最高优先级没有提升权限；同名解析与不同名正文的裁决分开核对。

## 3. 使用本地脚本

对本地 Agent Skills 格式，平台标识使用小写字母、数字和单连字符，最长 64 字符；例如 `cursor`、`gemini-cli`、`my-agent`。这些示例只是标签，不代表已经提供该产品专用规则。平台名未确认时用 `generic`，确认后将其换成真实标识，避免混合多个环境。

从 [通用来源模板](../assets/generic-sources.example.json) 复制本地清单，替换目录和证据，再执行：

```bash
python3 "<skill-dir>/scripts/checker.py" --platform generic --project "<project-dir>" --manifest "<local-dir>/sources.json" --output "<local-dir>/inventory.json"
```

`generic` 或任何未提供专用适配的平台使用项目中存在的共享 `skills/`、显式 `--skills-dir`、sources、runtime 和 governance。不会从项目/home 猜测 `.agents/skills`、`.trae/skills` 等专用位置，也不会解析 Codex 禁用配置或套用其调用策略。仅明确的 runtime 路径仍能完成来源发现；没有技能来源时，`discovery.status=unconfirmed` 并列出补证需求。

有专用适配的平台沿用其发现线索。混合多个平台时重复 `--platform`，每个平台单独保留身份和覆盖；不要将通用平台的文件误标为当前宿主正在使用。

Manifest v1 结构与原脚本兼容，`platform` 和 `runtime_complete` 的键接受上述标识。运行时断言仍需真实证据；完整列表也只证明本次暴露状态，不证明正文共同加载。

## 4. 无文件或其他格式时

通过宿主允许的只读接口取得列表和候选详情，按第 2 节记录等价清单；查询只取本次审计所需字段。使用真实工具签名，不要求某个平台特有工具必须存在。

按主流程对完整名称/描述清单初筛，然后阅读候选正文、影响判断的资源及治理要求。用户提供导出材料时确认日期和完整性；不要将历史导出当成实时清单。无法取得正文时交付可确认的触发竞争、来源关系和覆盖缺口，不声称完成正文冲突审计。

默认在当前对话报告。用户要求文件时按授权位置保存；托管平台不能导出某些材料时，报告证据定位和限制，不绕过访问边界。

## 5. 判断和验证边界

所有平台使用主流程中的相同结论分类和反证要求。未知同名规则不表示“必然覆盖”或“必然共同加载”；未知裁决不表示已经确认无裁决。只根据可确认的条件提出最小建议。

通用适配测试验证输入、枚举、身份隔离和未知状态的处理。某个真实平台的路由、加载、插件及权限行为，仍需在该版本环境中分别观察。新增专用适配前核对官方入口及可见配置，并增加相应回归与语义场景。
