# 安装衔接

只有用户要求安装时执行本流程。沿用会话中已明确的候选、作用范围与目标平台授权；必要信息可以从环境或已有规范确定时继续执行。

1. 确定实际安装单元和目标。单个 Skill、依赖共享资源的集合、Claude Code Plugin、OpenClaw Plugin 不能使用同一种复制方式。以当前上游说明和宿主平台的安装规范为准。
2. 重新确认上游当前发布内容及安装工具来源。公开来源清单不锁定版本；检查过程中可记录所核验的提交或包摘要，以防下载与核验内容变化。
3. 检查目标同名目录。用户未授权替换时保留原目录；用户已要求更新或替换时保留可恢复旧文件，完成新文件核验再切换。
4. 下载到宿主允许的隔离暂存位置，保留上游文件和资源布局。优先使用官方安装/解析工具；工具不能保证碰撞保护和资源完整性时先暂存。
5. 使用 YAML 解析器校验实际 SKILL.md。保留上游可加载的引号、额外元数据与历史资源结构；不为了统一格式擅自改写第三方内容。
6. 检查本 Skill 校验器能识别的文件引用，并另外核对动态路径、共享脚本、工作目录、运行时及认证依赖。保存全部相对文件路径与哈希；符号链接同时核对原链接目标和所需实体。
7. 按对应平台完成原子安装或官方安装流程，保留必需共享资源。核对最终 SKILL.md 存在，最终文件/链接清单与暂存清单一致。
8. 报告实际位置、安装内容、加载方式和剩余要求。文件成功落盘才能称文件安装成功；没有执行业务流程时只报告静态检查。

当前 Vercel skills CLI 的来源与选项：

- 官方仓库：`https://github.com/vercel-labs/skills`
- 官方说明：`https://github.com/vercel-labs/skills/blob/main/docs/commands.md`
- 工具包来自 npm 的 `skills`；使用时明确 npm 仓库并获取最新版。

已核实支持该安装方法后，可按实际候选和目标 Agent 生成：

```bash
npx --registry=https://registry.npmjs.org --yes skills@latest add "上游仓库" --skill "实际技能名" --agent "实际Agent"
```

用户级安装按官方说明加 `-g`。`--yes` 在这里仅用于 npx 包确认；来源包的碰撞和替换策略仍须核对。当前 CLI 需要 Node.js 22.20+，使用前读取上游最新要求，不把这一观察当作永久兼容性承诺。

ClawHub、LobeHub 和 SkillHub 的包按各自当前安装说明处理；不要把网站目录 ID 当作 GitHub 仓库路径。官方 CLI 的默认目录可能不属于当前宿主，显式核对实际目标。

需要配套 CLI、微信指定版本、外部模型、共享 Python 环境或激活码时，分别说明和落实用户已授权的步骤。Skill 文档复制成功不代表这些运行条件已经满足。

读取和校验阶段不运行下载内容中的脚本，不发送测试消息，不执行持仓、分析或发布等业务流程来证明可安装。用户明确要求运行验证时按真实用途和授权范围验证，并单独报告其结果。
