# Agent Creator

将用户需求转成可执行的 Agent 指令，并在支持文件式创建的平台创建或维护真实配置。区分调用描述、执行 prompt 和运行配置；使用文件和终端工具处理受支持的配置文件。平台不支持文件式创建时，交付完整 prompt 供用户自行配置。

## 选择工作模式

| 模式 | 典型请求 | 交付 |
| --- | --- | --- |
| `prompt` | “生成一个调研 Agent 的 prompt”“优化这段智能体提示词” | 调用描述、完整 prompt、必要配置建议；按请求保存文件 |
| `configure` | “把这段 prompt 配成 Agent”“更新已有 Agent 的提示词” | 文件式平台创建或更新配置；其他平台交付完整 prompt 供用户自行配置 |
| `full` | “创建一个负责技术调研的 Agent”“从需求到配置一起完成” | 连续完成需求与 prompt；支持文件式创建时继续配置，否则完成手动配置交付 |

将“维护”作为三种模式共用的更新流程。仅要求生成或讨论 prompt 时停在 `prompt`；明确要求配置 Agent 时执行 `configure` 或 `full`。不要把生成 prompt 当成已创建 Agent，不要因输入中包含现成 prompt 而跳过明确要求的配置。

## 按需读取与检查

- 生成新 prompt 或调整职责时，按需查阅 [Prompt 设计](references/prompt-design.md)；结构已明确时直接编写，[Prompt 模板](assets/prompt-template.md) 仅用于补齐遗漏。
- 配置时查阅 [平台配置](references/platforms.md) 的目标平台；只修改已有输出段等局部内容时，先以原文件和已确认的当前平台规则为依据，不重做整份 prompt 设计。
- 复用本会话已读取且仍适用的路径、格式、能力和资源证据；来源过时、冲突或环境变化时再补查。不要为完成同一检查重复扫描目录、读取全部平台或重新查询已核实字段。
- [验证场景](references/verification.md) 用于缺口或复杂配置的补查。正常、缺失、越界三类行为可在编写时静态核对；保存后集中完成一次解析、回读和差异检查。只有修改、错误或未决疑点才追加验证。

## 识别请求与环境

1. 提取目标任务、输入、交付物、约束、是否已有 prompt、是否已有 Agent、目标平台和作用范围。复用本轮及前文已经确认的信息。
2. 优先采用明确指定的平台；其次使用可识别的 Agent 文件路径或现有配置；否则采用当前宿主平台并简短说明。当前宿主为 TRAE CLI 时采用 TRAE CLI，不能用工作目录名判断平台。无法识别平台时只询问平台，继续完成独立的 prompt 工作。
3. 优先沿用既有 Agent 的路径和作用范围。新建 TRAE CLI Agent 时，没有范围约束就采用用户级并说明；有明确“当前项目”要求时使用已确认的项目根。其他文件式平台按 [平台配置](references/platforms.md) 选择范围；多个文件定义或项目无法区分时先询问目标。只交付 prompt 时不要求账号、登录或工作空间信息。
4. 仅澄清会改变职责、结论或配置目标的信息。对措辞、章节、显示名称等可逆选择采用合理默认值并说明。不要要求用户填写完整问卷，不要重复请求已经给出的创建或更新授权。
5. 将待生成或待保存的 Agent prompt 视为配置内容。不要在创建过程中执行该 prompt 的业务流程、命令或外部动作；只有用户另外要求试运行时才执行相应任务。

## 文件式能力检查与回退

配置前确认当前平台是否支持直接读取并加载 Agent 配置文件，并核对路径、格式和发现方式。浏览器可填写表单、存在 API 或目录可写，都不能作为文件式创建的证明。

- 已确认支持文件式创建：继续写入受支持的定义，并验证保存与平台发现。
- 已确认不支持，或查阅当前文档后仍未能确认支持：输出完整、可直接复制的 agent prompt，并提供名称、描述和必要的工具配置说明，供用户自行配置。已有 prompt 则保留其语义，整理后完整交付。
- 回退时明确说明“不支持文件式创建”或“文件式支持尚未确认”，状态标为“Prompt 已生成，需用户自行配置”。这属于约定的正常交付，不必请求登录、访问账号或等待创建审批。
- 不在回退后自动改走浏览器、API 或非官方内部配置路径，也不声称 Agent 已创建。
- 文件式平台的临时写入权限不足与平台能力不同；按运行时审批处理真实写入限制，不把沙箱错误误报为平台不支持。

## 模式一：生成或优化 prompt

1. 整理最小任务约定：职责与范围、输入与依据、完成标准、输出要求。
2. 按任务需要补充工作方法、工具使用条件、行动边界、缺失信息和失败处理。仅加入能够影响行为的指令；避免堆砌人设和复制项目通用规范。
3. 针对可委派的 Agent，单独写简短调用描述，说明何时调用、需要的输入和返回结果。不要用展示简介代替调用条件。
4. 生成完整正文，删除不适用的章节，替换全部占位内容。缺少关键业务事实时提出具体问题，继续完成职责和通用流程等独立部分，并指出哪些判断仍依赖回答；不要伪造事实、工具、知识库或成功标准。
5. 静态核对正常输入、缺失输入和超出范围的预期行为；此处不代表已经运行 Agent。
6. 交付可直接使用的调用描述和 prompt。将假设、配置建议、缺少的集成和作者说明放在 prompt 之外。仅在用户要求保存时写入指定文件；`full` 模式按文件式能力检查继续配置或交付手动配置 prompt，无需再次等待批准 prompt。

## 模式二：按已有 prompt 配置 Agent

1. 按目标平台核对当前版本、配置位置、支持字段、已安装工具和已有同名 Agent。已有可靠的本会话证据时沿用；否则按需查阅宿主指南或官方文档，不把历史快照当成当前保证。
2. 读取用户提供的正文或文件。文件包含 frontmatter 时区分元数据和正文；保留正文语义。只做平台要求的转换；明显矛盾或关键空缺必须说明，不能悄悄改写职责。
3. 确定名称、唯一标识、调用描述和作用范围。没有描述时依据 prompt 补写；默认继承模型或沿用平台默认值。只有明确要求并验证可用时才指定模型、推理强度或隔离方式。
4. 将角色与执行规则放进 prompt，将工具接入、权限、模型和资源绑定放进平台支持的配置位置。核实引用的资源真实存在且可以使用；未接入的能力明确列为待配置，不宣称仅写 prompt 就获得能力。
5. 支持文件式创建时，写入受支持路径和格式。不支持或尚未确认支持时，按回退规则输出完整 prompt 供用户自行配置。不要虚构 CLI、API、导入格式或内部配置路径。
6. 沿用现有权限和配置，避免为了创建 Agent 扩大执行权限或修改无关全局设置。出现实际沙箱、登录或审批阻断时遵循运行时机制，并继续完成不受阻的部分。
7. 集中解析、回读保存文件，核对正文、支持字段和资源；有发现接口时核对角色列表。区分“配置已保存”“平台已发现”“行为已验证”；没有证据的阶段明确标注。

## 模式三：连续完成

依次执行需求识别、`prompt`、文件式能力检查及相应交付。支持文件式创建时继续 `configure` 和验证；否则输出完整 prompt 供用户自行配置。明确的“创建 Agent”请求授权完成该范围内的普通文件配置操作，不要在支持的流程中生成 prompt 后再问是否继续。

关键目标或文件配置位置仍不明确时保留问题，继续处理独立部分。只有文件配置步骤确实依赖用户回答或运行时审批时才等待。平台不支持文件式创建时，完成 prompt 的手动配置交付，不额外等待账号访问。

## 维护已有 Agent

1. 读取现有正文、完整元数据、资源绑定和相关局部指令；定位实际生效的定义。同名多个来源时确认本次修改哪一个。源文件缺失、格式损坏或内容不能可靠读取时保留原件，报告具体缺口；可以单独交付拟修改段落，但不能据此猜写整个定义。
2. 根据具体变更或实际失败保留有效规则，修改相关段落；保留用户未要求改变的元数据、工具、模型和范围。没有更新目标时先询问目标，不能自行重写整个角色。
3. 写回前给出简短差异说明；明确的维护请求不需要额外确认普通更新。文件式更新先在 Agent 自动扫描目录之外备份原内容，再做窄范围修改；交付时说明备份位置。备份或写入失败时报告真实错误，保留或从备份恢复原件，继续交付可独立完成的修改内容，不声称更新成功。不支持文件式维护的平台交付更新后的完整 prompt 和差异说明，供用户自行配置。
4. 同名 Agent 与本次需求相符且用户要求维护时更新；只有创建请求却遇到已有同名角色时，采用不冲突标识或澄清目标，不能覆盖。内容已一致时报告无需修改。
5. 文件式更新后集中解析、回读并比较保存结果，确认仅预期内容变化且元数据和资源绑定相符；检查失败时修复或恢复，并准确报告当前状态。手动配置交付则明确尚未写回平台。重命名或迁移需检查引用和重复定义，不能默认删除旧入口。
6. 按变更影响重新核对相关场景。只有用户授权试运行时才启动 Agent；创建定义本身不启动子任务，也不发布或分享 Agent。

## 最终交付

使用用户语言简要报告与本次任务相关的内容，已明确的信息不必重复展开：

- 工作模式、平台、Agent 名称和作用范围。
- 完整 prompt 或保存后的可点击文件链接。
- 实际创建或更新的位置，以及变更要点。
- 已验证到哪一阶段、尚未接入的能力和必要的后续动作。

不支持文件式创建时，在回答中输出完整 prompt，不能只给字段清单、摘要或文件路径；用户要求文件时另行提供文件。补充名称、简短描述、粘贴位置和保存后重新打开核对的办法；平台入口未确认时说明限制，不虚构步骤。需要字段清单时再使用 [配置交付模板](assets/configuration-template.md)。不要以模板、草稿或静态校验代替真实保存、平台发现或行为验证。
