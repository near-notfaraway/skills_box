# 多引擎搜索

根据语言和用途选择多个搜索引擎，聚合检索结果，并用来源链接支持回答。

辅助脚本支持按名称调用目录中的全部 16 个中文及全球搜索入口，覆盖通用网页、
偏隐私的检索、微信公众号文章和计算型知识查询。Google News 与 Bing RSS 是
目录之外的额外订阅源路径。脚本通过 HTML 解析和可选的浏览器渲染执行搜索；
入口是否可用仍取决于服务提供商和当前环境。

## 核心搜索能力

- **引擎选择**：从目录中选择中文、全球、新闻、偏隐私或计算型搜索入口。
- **查询构造**：按任务需要使用高级操作符、时间范围、DuckDuckGo Bangs 和多语言查询。
- **多引擎检索**：调用适合的引擎，聚合结果标题、链接及可获取的日期信息。
- **结果整合**：比较相关来源，用引用支持对用户问题的回答。

选择地区性、偏隐私、专用或用户指定的引擎时，阅读
[引擎目录](references/engine-catalog.md)。使用高级操作符、时间范围、
DuckDuckGo Bangs、WolframAlpha 或多语言查询时，阅读
[查询策略](references/query-strategies.md)。

失败回退、URL 去重、覆盖诊断和来源核验是搜索流程的增强能力。
执行任务时，始终遵循下文“搜索增强能力”的规则。

## 执行流程

### 1. 选择引擎并构造查询

先明确：

- 搜索主题、关键实体和所需信息；
- 查询语言、地区和来源类型；
- 有时效要求时，对应的日期范围；
- 任务需要的引擎覆盖或来源比较；
- 用户是否指定了必须实际尝试的引擎。

采用满足任务所需的最小范围。先区分任务目标：

- **事实研究**：目标是找到并读取足够的独立来源正文；引擎覆盖只是发现手段。
- **多引擎检索**：目标包括多个引擎家族的候选覆盖。
- **具名入口检查**：目标是逐个尝试用户指定的入口并分别报告结果。
- **专用入口任务**：偏隐私检索或 WolframAlpha 本身就是用户要求的一部分。

事实研究默认尝试两个独立引擎家族，但如果已经读取到满足要求的官方来源和独立来源
正文，应停止继续探测引擎，只披露实际覆盖。不要为了凑覆盖数量而延长已经完成的
来源核验。多引擎检索和具名入口检查仍按用户要求执行全部必要路径。

同一提供商的不同入口、地区版本或订阅源归为同一家族。

按任务选择引擎组合：

- 中文公开网页：优先百度、搜狗，再考虑地区性浏览器入口；
- 全球公开网页：优先 Bing RSS、DuckDuckGo 和 Brave；
- 新闻：Google News 加一个独立网页搜索家族；
- 偏隐私的检索：DuckDuckGo、Startpage、Brave 或 Qwant；
- 计算型知识：使用 WolframAlpha，不将其计入通用网页的交叉核验。

为减少无关请求，普通任务优先使用任务配置，而不是兼容模式下的宽泛默认组合：

| 配置 | 入口 |
| --- | --- |
| `global-web` | Bing Global、DuckDuckGo、Brave |
| `cn-web` | 百度、搜狗、Bing CN |
| `news` | Google News、Bing RSS、DuckDuckGo |
| `privacy` | DuckDuckGo、Startpage、Brave、Qwant |
| `computation` | WolframAlpha |

查询词保持简洁。按需增加站点限制、精确短语、时间筛选或实体名称的译法；
不同引擎的具体语法见查询策略参考。

列出全部 16 个入口及其适配范围：

```bash
python3 "<skill_dir>/scripts/reliable_search.py" --list-engines
```

### 2. 执行所选引擎的搜索

获得安装授权后再安装依赖：

```bash
python3 -m pip install -r "<skill_dir>/requirements.txt"
```

运行辅助脚本：

```bash
python3 "<skill_dir>/scripts/reliable_search.py" \
  "query terms" \
  --profile global-web \
  --min-engines 3 \
  --limit 10
```

根据任务将 `global-web` 换成 `cn-web`、`news`、`privacy` 或 `computation`。
未指定引擎时仍保留包含 Google News、Bing RSS、DuckDuckGo、Brave、百度和搜狗的
兼容组合，但新任务不要依赖该宽泛默认。未使用 `--check-all` 或 `--engines` 时，
达到要求的覆盖数量后停止。

需要指定引擎时：

```bash
python3 "<skill_dir>/scripts/reliable_search.py" \
  "query terms" \
  --engines google,bing-global,yahoo \
  --min-engines 3
```

指定引擎的任务会尝试每个所选入口，即使已经达到覆盖要求。
`google` 表示 Google 网页搜索，`bing-global` 表示 Bing 国际版网页入口；
不能将它们悄悄替换成订阅源。

检查目录中的全部入口，或所有指定入口：

```bash
python3 "<skill_dir>/scripts/reliable_search.py" \
  "Python pathlib documentation" --check-all --headed --limit 30
```

`--transport auto` 是默认模式，通常先尝试 HTTP，必要时再尝试同一入口的浏览器
路径。Startpage、Ecosia 和 Qwant 优先使用浏览器，这些偏好记录在引擎目录中。
Startpage 会先打开不带查询词的入口，再提交网站真实的 POST 表单。
`--transport http` 只需要 Python 依赖；即使入口优先使用浏览器，也始终只走 HTTP。
`--transport browser` 获取浏览器渲染后的页面，但 RSS 路径仍使用 HTTP。

浏览器路径需要 `agent-browser` CLI 和 Chrome/Chromium。先运行
`agent-browser skills get core`，读取与本机 CLI 版本匹配的操作说明。
缺少 CLI 或浏览器时，遵循当前安装说明处理。`--headed` 显示任务窗口，
否则 Chrome 以无窗口模式运行。浏览器位于非标准路径时，使用
`--browser-executable "/path/to/chrome"`。
不同模式的实测结果和仍存在的服务限制，见
[验证范围](references/engine-catalog.md)。执行环境必须允许写入 CLI 的会话存储。

用户授权使用正常浏览器会话后，可以用 `--use-existing-browser` 自动发现正在运行
且支持 CDP 的浏览器，也可以用 `--browser-cdp "<port-or-CDP-URL>"` 指定连接。
如果浏览器已经通过 `agent-browser` 连上，使用 `--browser-session "<session-name>"`。
通过 `agent-browser session list` 查找会话名，再用
`agent-browser --session "<session-name>" get cdp-url` 检查连接。
当浏览器桥接无法接受另一条 CDP 连接时，也可以直接复用已有连接。

```bash
python3 "<skill_dir>/scripts/reliable_search.py" \
  "Python pathlib" --engines qwant \
  --browser-session "<connected-session-name>" --min-engines 1
```

实测中，Qwant 在已有浏览器会话内返回了真实结果，而新建临时会话显示搜索服务 403。
遇到这种情况，优先使用用户授权的正常会话；不能仅凭临时会话失败，就判断整个引擎
不可用。使用已有浏览器时，脚本只创建和关闭自己的任务标签，保留浏览器自身的网络
配置及会话状态，不能同时指定 `--proxy` 或 `--browser-executable`。
不会将浏览器配置目录、Cookie 或本地存储复制到 Skill 中。

已有授权使用的代理时，可以指定 `--proxy "http://host:port"`，或设置
`MSEARCH_PROXY` 环境变量。支持 HTTP(S)、`socks5://host:port` 和
`socks5h://host:port`；后者在代理端解析域名。安装 `requirements.txt` 可补齐
SOCKS 依赖。指定的代理同时用于本次 HTTP 和浏览器请求，覆盖继承的代理绕过规则，
不修改系统配置。代理 URL 必须包含主机和端口，不能包含凭据。
代理地址只保存在本机配置中，不写入可分享的目录索引。

网络超时、DNS 路由问题、服务端跳转和验证页面，需要可用的网络路径或服务提供商
正常的人工访问流程；解析器无法解决这些问题。不能换用另一家服务，却声称指定入口
已经成功。

默认情况下，脚本创建临时浏览器配置目录，并关闭自己的会话。使用已有浏览器时，
只关闭自己创建的标签。脚本会在该会话内跟随最多三个无法直接识别目标地址的
Google 或微信结果链接；其余链接标记为 `session_required`，不计入可用覆盖。

WolframAlpha 使用单独的计算查询：

```bash
python3 "<skill_dir>/scripts/reliable_search.py" \
  "2+2" --profile computation --headed
```

WolframAlpha 的结果区块输出到 `answers`，与网页结果和网页引擎家族覆盖分开。
用普通网页查询测试全部入口时，它可能不返回计算结果；判断该入口是否支持搜索前，
应使用适合的计算查询单独测试。

用户明确要求“用 WolframAlpha”时，只有 `answers` 中取得对应计算结果才算完成该
要求。访问失败后使用其他公开汇率或计算来源，可以补充答案，但不能把替代结果写成
WolframAlpha 成功。

### 3. 聚合并检查结果

检查排序后的标题和规范化链接，整合相关发现，再选择需要打开的来源。
通过 `seen_in_families` 查看哪些提供商返回了同一页面；共同找到一个页面，
只代表检索结果重合，不代表对事实的独立确认。

辅助脚本输出一份 JSON 报告：

- `status`：达到要求的网页引擎家族覆盖，或纯计算任务返回计算答案时，为 `ok`；
- `attempts`：每次 HTTP 或浏览器尝试的状态、URL、可用结果数、候选数和答案数；
- `engine_outcomes`：每个实际执行入口的最终结果及词项匹配诊断 `query_match`；
- `results`：排序后的规范化候选链接，以及返回它们的引擎家族；
- `answers`：计算结果区块的标签和值；
- `coverage`：要求覆盖的家族数量及成功的家族；
- `next_action`：脚本路径不足以完成任务时，为 `use_host_search`；
- `requires_source_verification`：始终为 true。

退出码 `0` 表示本次运行满足上述完成条件；在全部入口测试中，不代表每个引擎都成功。
退出码 `2` 表示报告仍可使用，但需要执行回退，或说明实际覆盖不足。

不能根据一次请求失败，就声称整个引擎不可用。报告实际观察到的路径，
例如“Brave HTML 路径返回 429”。

### 4. 执行有次数限制的回退

同一入口的自动浏览器回退会保留两次尝试。遇到验证码、JavaScript 验证、
禁止访问或限流时，不重试该路径。当 `next_action` 仍为 `use_host_search` 时：

1. 使用当前环境提供的宿主搜索工具或浏览器能力。
2. 先搜索同一组简洁查询词；相关性较差时，再修正一次查询。
3. 保留链接，标明实际使用的后端。除非工具明确标注，否则不能将宿主工具结果归于
   某个指定引擎。
4. 遇到验证码、禁止访问或重复限流时，停止该路径。
5. 改用其他允许访问的来源；不自动解验证、不导入个人浏览器状态，也不反复刷新。

用户明确要求测试某个引擎时，单独报告该引擎的结果。
其他后端可以帮助完成研究，但不能证明指定引擎已经可用。

用户要求“换搜索引擎”时，至少一个 DuckDuckGo 之外的具名引擎必须返回可用候选，
才能声称已完成换引擎检索。后端身份未披露的宿主搜索只能帮助定位来源，不能满足这
一要求。

用户要求偏隐私入口时，至少一个标记为偏隐私的入口必须返回相关且可用的候选链接，
才能声称偏隐私检索成功。仅记录 CAPTCHA、403、429 或空结果属于如实尝试，不属于
成功；可以继续用其他后端完成事实研究，但必须把原要求标为未满足。

高级操作符和时间筛选用于构造查询，本身不是证据。限制较多的查询没有结果时，
先简化一次，再考虑切换引擎。

如果标题和链接没有匹配任何受检查的拉丁字符查询词，脚本报告 `query_mismatch`，
不计入覆盖。缺少部分词项时，需要检查相关性，必要时修正一次查询。
这种保守的词项检查不能证明语义相关。

Bing Global 还会拒绝缺少任一受检查词项的结果集，但不要求匹配通用词
`documentation`、`docs` 和 `official`。原因是实测响应有时遗漏具体主题，
只匹配宽泛词项。这条规则可能排除使用同义词的相关结果；应检查诊断并调整查询，
再作判断。

DuckDuckGo Bangs 按实际跳转目标的家族计算覆盖。WolframAlpha 适合计算型知识，
不能用于独立确认公开新闻。

### 5. 核验来源正文

使用可用的抓取或浏览器工具打开最相关的候选页面。对每项重要结论：

- 确认正文支持该结论；
- 分别记录发布日期和数据截止日期；
- 优先使用一手来源或独立撰写的来源；
- 区分官方数据、第三方估算和转载报道；
- 多家媒体转述同一公告，不算独立的事实确认。

候选页面无法读取时，标记为“未核验”，并更换来源。

达到用户要求的来源数量和独立性后停止发现阶段。后续只补齐缺失的正文、日期或来源
归属，不再为提高引擎覆盖数字追加查询。每个引擎家族最多进行一次有实质变化的查询
修正；细微改词不应形成重试循环。

### 6. 输出报告

报告包括：

1. 有证据支持的结论、日期和引用；
2. 重要分歧或不确定性；
3. 引擎家族覆盖，以及有实际影响的失败路径；
4. 可能影响结论的来源读取限制。

除非用户要求比较引擎，否则只报告影响结论或明确要求是否完成的失败路径。不要输出
与答案无关的完整调试日志。

## 搜索增强能力

使用以下能力提高搜索完成率和回答质量：

- **失败回退**：保留被拦截、空结果、限流、服务端错误和网络错误的结果。继续尝试
  配置中的引擎，直到达到要求的家族覆盖或没有剩余路径，再执行必要的宿主工具回退。
- **结果去重**：规范化 URL，合并重复结果，同时保留各个贡献结果的引擎家族。
- **覆盖诊断**：只有返回可用标题和公开 HTTP(S) 链接的家族才计入覆盖。
  同一提供商的其他入口不算独立覆盖；只报告实际执行过的路径。
- **查询诊断**：显示匹配和缺失的拉丁字符词项，排除明显不匹配的结果集；
  语义相关性仍由 Agent 判断。
- **来源核验**：作出事实判断前，读取相关来源正文并核对日期。
  请求成功和结果排序不能证明来源中的说法。

解释失败或覆盖结果、修改辅助脚本，或判断搜索任务是否完成时，阅读
[可靠性约定](references/reliability-contract.md)。

## 开发与维护

运行离线测试，避免将字节码写入 Skill 目录：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s "<skill_dir>/tests" -p "test_*.py" -v
```

辅助脚本将候选检索与来源核验分开处理。不要声称解析器、HTTP 状态或排序分数
能够验证事实。
